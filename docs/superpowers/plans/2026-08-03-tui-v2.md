> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**钉死语义（勿再设计）**：

1. **消息树为唯一真相**：会话内容（user/assistant/reasoning/tool/verification/system-event）只存于 `Conversation`；命令反馈（`/help`、`/cost` 报表等 UI 回显）走 `AppState.echo: Vec<UiLine>`，不进树。渲染 = 树渲染 → 当前 pending → 回显。
2. **推理整段提交**：`ReasoningDelta` 只追加 `pending_reasoning`；`TextDelta`/`ToolCallStart` 先 flush 成 `Segment::Reasoning` 再落新段。不变量：任何时刻 pending_reasoning 不与已落段交错。
3. **折叠独立存储**：`HashMap<SegId, bool>` 在 AppState，不嵌消息树。默认：Reasoning 折叠、ToolCall 展开、成功结果截断 400、失败/验证失败醒目。
4. **命令注册表**：`Command { name, desc, keywords, args_spec, handler: &'static dyn CommandHandler }`，`#[async_trait] trait CommandHandler { async fn run(&self, ctx: &mut CommandCtx, args: &str) -> CommandOutcome }`。`CommandCtx { app: &mut AppState, caps: &TuiCaps }`；`TuiCaps` 持全部注入能力 Option（factory/router/session/mcp_probe/undo/skills_paths/mcp_servers + model 状态）。静态分发，async-friendly，无双轨分叉。
5. **TuiRunner 保留全部字段与 builder**，新增 `with_theme(Theme)`、`with_workspace_root(PathBuf)`；事件循环迁 `app/mod.rs`，`handle_command` 改为查注册表。
6. **Focus**：`Conversation | Input | Sidebar | Palette | Completion | Confirm`；`AppState.handle_key` 拆为 `handle_key(key) -> KeyAction` 分派到各焦点处理器。现有编辑键位语义零破坏。
7. **主题**：`Theme` 语义色映射，`theme_from_env()` 解析 `DEEPSEEKNOVA_THEME`（`codex` 默认 | `dark` | `light`，未知回退 codex + System 提示）；现 `style_for/diff_spans/status_segments` 迁移为 `Theme` 方法/收 `&Theme`。
8. **布局**：纵向 对话区 + 状态行(1) + 输入区(Length 5) + 提示行(1)；横向 侧边栏（`Ctrl+\` 开合、Tab/Ctrl+1..5 切面板、<90 列自动隐藏）。
9. **@补全**：`AtCompleter::new(workspace_root, files: Vec<String>)` 由 CLI 注入文件清单，TUI 不扫文件系统；`@` 触发、`↑↓` 选、`Enter` 插入、`Esc` 关。粘贴路径转换本期仅实现"检测已存在路径前缀转 `@相对`"纯函数（`paste_to_at`），CLI 接线视为增强可后补（见 Task 12）。
10. **/copy**：`y` 键 / `/copy` 命令复制当前聚焦消息文本；剪贴板经 `arboard` 可选依赖探测，缺失时打印文本（降级不报错）。若 `arboard` 引入编译问题（macOS 依赖坑），回退方案：仅打印 + 状态行提示，`arboard` 不启用（Task 12 验证点）。
